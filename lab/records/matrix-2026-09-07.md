## What changed against the 2026-09-06 baseline

- **Verdicts: no regression.** 20/20 comparable cells passed then,
  and every one of those cells passed again now; the matrix grew by
  the knowledge-01 row (now four heads deep) and the qwen annex.
- **claude durations roughly doubled; attribution is the router, not
  the harness.** 09-06 claude cells ran 6.5-20.1s on the then-openrouter
  sonnet/haiku tiers (gemini-2.5-flash / openrouter-auto). With every
  tier muse-backed, claude cells run 18.0-47.4s (kali) and
  19.0-122.4s (ubuntu): muse is a reasoning model and its thinking
  budget is spent inside every call. The graded outcome is
  unaffected (same full-verification passes at similar or leaner
  call counts than codex).
- **Tool-call economy ordering is stable across sessions**: claude
  heads leanest (5-10 calls), qwen mid (6-13), codex heaviest
  (6-18). Same shape as 09-06, now with a fifth head agreeing.

## qwen annex — first graded qwen-head cells

The qwen-code lane is runner-driven from the native kali install
(node 24.15.0, `@qwen-code/qwen-code@0.23.0`, token-plan
subscription, 0600 `~/.qwen/settings.json`). 6/6 matrix cells +
3/3 variance attempts pass with valid chains and closes. The
Windows npm install stays transport-blocked for graded cells: the
hermetic argv gate (npm-style `.cmd` shim replicated, multiline
prompt in, recorded argv out) shows cmd.exe truncates the runner's
multiline attempt prompt at the first newline and mis-splits argv
(`argv count: 6 (expected 5)`); single-line probes pass, which is
why the lane's earlier smoke reached the provider. Details in
`lab/validation-results.md` (qwen-code section).
